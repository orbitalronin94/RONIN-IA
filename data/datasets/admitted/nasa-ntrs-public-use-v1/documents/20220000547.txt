LCBC RECAP

• Presented an automatic approach to maintain sufficient overlap between 
hyperbolic meshes in auto-generated surface and volume grid systems

• Prevented face/off-body meshes from filling in gaps in overlap region 
(avoids mismatch in grid spacing)

• Reduced manual effort needed to maintain overlap (hours to minutes)
• Demonstrated applications of LCBC in both surface and volume meshing 

on two aeronautical vehicles



36

SOFTWARE MODULES (1)
EGADS2SRF

• Interface to geometry file using Engineering Sketch Pad (ESP) from MIT

• Input
• Boundary Representation (BRep) solid in a STEP or IGES file
• Global parameters: max grid spacing, max turning angle, max stretching 

ratio, min number of points on an edge
• Optional geometric components specification file
• Options (face removal for open boundary cases, single component meshing)

• Output
• Surface triangulation (CART3D format)
• Discretized Faces (PLOT3D surfaces)
• Discretized Edges (PLOT3D curves)
• Edge/face topological relationship (text)
• Input parameters file for POGS (text)



37

SOFTWARE MODULES (2)
POGS (Pre-processor for Overset Grid Simulations)

• Generate edge and node surface meshes and compute surface connectivity
• Generate near-body and off-body volume meshes
• Perform volume mesh domain connectivity * Work in progress
• Write input files for flow solvers and component aero-loads computation

Input
• Output files from EGADS2SRF (or files with equivalent data)
• Optional geometric components specification file

Output
• Surface grids with iblanks (PLOT3D surface grids)
• Surface grid donor stencils data file (SINTOUT)
• Near-body + Cartesian off-body volume grids with iblanks (PLOT3D volume grids)
• Volume grid donor stencils data file (INTOUT) * Work in progress
• Input file for component aero-loads computation (FOMOCO)
• Input file for flow solver (OVERFLOW & LAVA)

WORK IN PROGRESS AND CONCERNS

Work in progress
• About 95+% of unacceptable meshes - concave regions of hyperbolic meshes 

(challenge #5)
• Remaining unacceptable meshes - choice of Node mesh initial curve at saddle 

points or marching scheme selection
• Automatic surface mesh local refinement based on orphan point locations
• Volume mesh domain connectivity automation

Geometry Input Concerns
• BRep solid geometry not always available
• Poor choice of BRep topology from geometry construction 
• Face parameter space not lined up with surface curvature 
• Unnecessarily excessive number of Edges and Faces on smooth geometry

CONCLUDING REMARKS
• Automation scheme 

• Surface domain decomposition into face, edge, node meshes
• Grid point distribution
• Hyperbolic / algebraic meshes
• Domain connectivity (surface and volume)
• Flow solver and post-processing input file generation

• Recent features: open boundary geometries, component specification

• Two software modules: egads2srf, pogs (internal testing only)

• Successful application to a variety of aeronautical vehicles

• Percentage of acceptable auto-generated meshes (75% - 100%)

• Significant reduction in manual effort and time: hybrid auto and 
manual meshes (weeks/months -> days, days -> hours)
