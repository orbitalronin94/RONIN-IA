<div class="slide-content"><p>What is GPX2?</p>
<p>3U technology demonstration CubeSat</p>
<p>Increase the Technology Readiness Level (TRL) of hardware components</p>
<p>LaRC Flight Computer Processing Unit (FCPU), uCAM-III cameras, and chassis made from Windform XT 2.0</p>
<p>Increase knowledge/experience utilizing Iridium Short Burst Data (SBD) communications</p>
<p>Build on NASA Ames experience utilizing SBD</p>
<p>Attempt an off-the-shelf Align experiment via the NovAtel OEM719 GPS Receivers</p>
<p>Aimed at measuring a known distance between the G5 Antennae via Align relative positioning</p>
<p>Workforce development (small and young team)!</p>
<p></p>

<div class="slide-master-content"><p>2023 Flight Software Workshop </p>
<p>GPX2</p>
<p>‹#›</p>
</div>
<div class="slide-content"><p>Launched July 2nd 2022 on Virgin Orbit’s LauncherOne as part of the “Straight Up” mission</p>
<p>Successfully reached a ~500km circular orbit</p>
<p>Received first health and status beacon ~45 minutes after deployment</p>
<p>Demonstrated Iridium SBD transmissions and are working to further characterize them</p>
<p>&gt;1MB through Iridium SBD thus far</p>
<p>Demonstrated uCAM-III camera operates on orbit</p>
<p>26 images from orbit transmitted thus far</p>
<p>Demonstrated NovAtel OEM719 receivers are operational, unfortunately an Align mode lock has not been achieved</p>
<p>Have been operating nominally since launch!</p>

<div class="slide-master-content"><p>2023 Flight Software Workshop </p>
<p>GPX2</p>
<p>‹#›</p>
</div>
<div class="slide-content"><p> LaRC developed flight hardware and software </p>
<p>LaRC Flight Computer Processing Unit (FCPU) design utilizing STM32F407VG chip</p>
<p>16MHz Internal Clock, 196KB RAM, 1MB Internal Flash, Direct Memory Access (DMA) controller</p>
<p>32MB external flash chip running Little File System (LFS)</p>
<p>LaRC flight software (FreeRTOS) and ground software (Python/COSMOS)</p>

<p>GPX2 Ground Software Architecture</p>
<p>Two data interfaces into GPX2</p>
<p>GSE: COSMOS utilized as primary ground testing/development software </p>
<p>LaRC Python scripts leveraging COSMOS interface for definitions for database logging.</p>
<p>COSMOS utilized heavily for development and testing (test script running, limits monitoring, telemetry logging, etc.)</p>
<p>MODEM: (Iridium) Interfaces via email</p>
<p>LaRC Python GUIs for command crafting and telemetry processing (stitching packets back together)</p>

<div class="slide-content"><div class="embedded" id="slide8_rId2"></div>
<p>Leveraging DMA controller optimized capabilities of the resource limited microcontroller</p>
<p>DGPS, IMU, EPS, ADC, and Flash interfaces all heavily utilize the onboard DMA controller</p>
<p>2x UART, 2x I2C, 1x ADC, and 1x SPI</p>
<p></p>
<p>Utilizing Little File System (LFS) onboard for long term telemetry storage added flexibility and data integrity to GPX2</p>
<p>LFS performs dynamic wear-leveling, power-loss resilience, CRC checking, and bounded RAM/ROM usage</p>
<p></p>

<div class="slide-content"><p>Flexible ground software design allowed for sharing and collaboration of test and flight data</p>
<p>Ground software populates a MariaDB database via a Python script that pulled from COSMOS</p>
<p>Flexible Python “glue” with a single point of truth for telemetry and command definitions</p>
<p>Utilizes LaRC hosted Grafana database viewer</p>
<p>Easily able to add users and customize their views</p>
<p>Remote viewing/sharing of test data for project members and management during integration, testing, and operations activities</p>
<p>Great for timestamped time-series data</p>
<p>Not ideal for viewing images</p>

<div class="slide-content"><p>Utilize telemetry indexing to reduce data bandwidth and increase flexibility</p>
<p>GPX2 Iridium SBD bandwidth is extremely limiting (average throughput ~3.5kB per day)</p>
<p>The software team devised a way to splice and index the system’s logged telemetry</p>
<p>Late addition to the software development effort</p>
<p>Able to implement this feature quickly (&lt; 1 week) and it has proven invaluable on-orbit</p>
<div class="embedded" id="slide10_rId2"></div>

<p>‹#›</p>

<div class="slide-content"><p>Importance of flight-like flatsat for software development and testing</p>
<p>Complete system with flight-like hardware</p>
<p>Able to run end-to-end testing years before launch</p>
<p>Caught a lot of issues early!</p>
<p>Importance of utilizing automated system level testing</p>
<p>Wrote system level tests via COSMOS “TestRunner” framework</p>
<p>Sends every command within the system, checks for correct number of Rx/Tx bytes, relevant counters incrementing, and reports all error masks before/after command processing</p>
<p>Produced output logs that proved invaluable</p>
<p>Could go back and check historical test runs as needed</p>
<p>Allowed automation of TVAC testing!</p>
<p>Every TVAC test point ran 33 tests in ~5min</p>

<div class="slide-content"><p>Stay connected with hardware/software vendors regarding the project specific configuration details</p>
<p>Spurious watchdog reset discovered on GOMSpace Electrical Power System (EPS) during TVAC</p>
<p>This meant random unintended power cycles</p>
<p>Evidence of this reset was found in archived test data</p>
<p>The vendor admitted to having knowledge of this</p>
<p>They even had a patch for it! </p>
<p>It was too late for GPX2 to apply this patch</p>
<p>The software team quickly developed a FSW patch that allowed for mitigation of reset on-orbit</p>
<p>Problem continues to occur ~6hrs on orbit without hindering the mission</p>
<p>This issue could have been mitigated if there was better communication with the vendor</p>
<p></p>
<p>Lessons Learned (Integration &amp; Test)</p>

<div class="slide-content"><p>Have a detailed operations plan including who will staff this phase of the project</p>
<p>FSW engineers often become operators</p>
<p>Secure funding for software team</p>
<p>Automate operations as much as feasible</p>
<p>The team quickly learned it was clunky to manually operate the way it was originally planned</p>
<p>Over time, various scripts/tools have been developed for quality-of-life improvements</p>
<p>Enjoy the view!</p>

<div class="slide-content"><p>GPX2 is a 3U technology demonstration CubeSat developed by LaRC</p>
<p>Successfully launched via Virgin Orbit’s LauncherOne and operational since July 2nd, 2022</p>
<p>Key Lessons Learned</p>
<p>Leverage tools that are available to you (first step is to learn what tools are even available!)</p>
<p>Good software designs pay dividends</p>
<p>Automate things in an efficient way (work smart not hard)</p>
<p>Embrace being able to “fix-it-in-software”</p>
<p>Stay connected with vendors</p>
<p>Next Steps</p>
<p>Continue operations of GPX2 and monitor its health and status</p>
<p>Continue attempting Align experiments and characterizing Iridium SBD transmissions</p>
<p>Apply these software lessons to other LaRC projects and future CubeSat projects</p>
<p>Software reuse is already underway for some GPX2 software</p>
