What is GPX2?


3U technology demonstration CubeSat


Increase the Technology Readiness Level (TRL) of hardware components


LaRC Flight Computer Processing Unit (FCPU), uCAM-III cameras, and chassis made from Windform XT 2.0


Increase knowledge/experience utilizing Iridium Short Burst Data (SBD) communications


Build on NASA Ames experience utilizing SBD


Attempt an off-the-shelf Align experiment via the NovAtel OEM719 GPS Receivers


Aimed at measuring a known distance between the G5 Antennae via Align relative positioning


Workforce development (small and young team)!

Launched July 2nd 2022 on Virgin Orbit’s LauncherOne as part of the “Straight Up” mission

2023 Flight Software Workshop 


GPX2


‹#›








Leveraging DMA controller optimized capabilities of the resource limited microcontroller


DGPS, IMU, EPS, ADC, and Flash interfaces all heavily utilize the onboard DMA controller


2x UART, 2x I2C, 1x ADC, and 1x SPI





Utilizing Little File System (LFS) onboard for long term telemetry storage added flexibility and data integrity to GPX2


LFS performs dynamic wear-leveling, power-loss resilience, CRC checking, and bounded RAM/ROM usage

Flexible ground software design allowed for sharing and collaboration of test and flight data

2023 Flight Software Workshop 


GPX2


‹#›





Utilize telemetry indexing to reduce data bandwidth and increase flexibility


GPX2 Iridium SBD bandwidth is extremely limiting (average throughput ~3.5kB per day)


The software team devised a way to splice and index the system’s logged telemetry


Late addition to the software development effort


Able to implement this feature quickly (< 1 week) and it has proven invaluable on-orbit

2023 Flight Software Workshop 


GPX2


‹#›





Importance of flight-like flatsat for software development and testing


Complete system with flight-like hardware


Able to run end-to-end testing years before launch


Caught a lot of issues early!


Importance of utilizing automated system level testing


Wrote system level tests via COSMOS “TestRunner” framework


Sends every command within the system, checks for correct number of Rx/Tx bytes, relevant counters incrementing, and reports all error masks before/after command processing


Produced output logs that proved invaluable


Could go back and check historical test runs as needed


Allowed automation of TVAC testing!


Every TVAC test point ran 33 tests in ~5min

2023 Flight Software Workshop 


GPX2


‹#›





Stay connected with hardware/software vendors regarding the project specific configuration details


Spurious watchdog reset discovered on GOMSpace Electrical Power System (EPS) during TVAC


This meant random unintended power cycles


Evidence of this reset was found in archived test data


The vendor admitted to having knowledge of this


They even had a patch for it! 


It was too late for GPX2 to apply this patch


The software team quickly developed a FSW patch that allowed for mitigation of reset on-orbit


Problem continues to occur ~6hrs on orbit without hindering the mission


This issue could have been mitigated if there was better communication with the vendor

Key Lessons Learned


Leverage tools that are available to you (first step is to learn what tools are even available!)


Good software designs pay dividends


Automate things in an efficient way (work smart not hard)


Embrace being able to “fix-it-in-software”


Stay connected with vendors


Next Steps


Continue operations of GPX2 and monitor its health and status


Continue attempting Align experiments and characterizing Iridium SBD transmissions


Apply these software lessons to other LaRC projects and future CubeSat projects


Software reuse is already underway for some GPX2 software
