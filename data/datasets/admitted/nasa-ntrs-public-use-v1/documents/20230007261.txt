Introduction


2


The Space Launch System (SLS) Program computes rollout loads using measured base drive interface accelerations as the forcing function


Measured interface accelerations between Crawler Transporter (CT) and Mobile Launcher (ML) used as an enforced acceleration in the analysis of the SLS ML and vehicle model


This data is from the Shuttle program, Ares program, and early ML only rollout tests


CT speed placard of instituted to minimize loads


Rollout set the design load on the Multi-Purpose Crew Vehicle (MPCV) for some primary structure loads (section loads) and for the Vehicle Stabilizer (VS) tangent load


The Dynamic Rollout Test (DRT) was the first rollout with the SLS vehicle


New configuration not represented in base drive data used for design analysis


Significantly more weight on the CT than existing data


The item being carried could have impact on characteristics of base drive accelerations


Real-Time Monitoring (RTM) was recommended for the DRT to verify that loads remained below design values during rollout


Concern with possibility of high loads exceeding design limits


Tuned nature of loads and high sensitivity of loads to CT speed


Uncertainty in rollout forcing functions


Lack of experience in performance of Vehicle Stabilizer (VS) 


Verify adequacy of CT speed placard given model and forcing function uncertainty


Opportunity, sensors associated with Integrated Modal Test (IMT) made RTM a feasible option


This presentation provides an overview of the RTM process

Measurement Requirements


9


The PEQ load was estimated using acceleration and anemometer data obtained real-time during rollout


1 tri-axial accelerometer at station 


2 bi-axial accelerometers at station 


3 tri-axial accelerometers at station 


Anemometer measurement at top of ML


Additional recoveries included VS tangent strut loads and CT-ML interface accelerations


These are direct measurements, no indirect estimations are required


Some processing was applied


Filtering to remove noise or to focus on lower frequencies


Rotations or sign changes to account for as-installed orientation


MATLAB function created to return PEQ estimate from measured acceleration data combined with measured winds


Includes multiple redundancies for accelerometer locations


Includes error checking and compensation for missing channels


Primary transducer for wind load is anemometer data but tower strain gauge data included as a backup to anemometer


Load estimate can compensate for missing / dead channels


Flag used to adjust load estimate for missing channels


Redundant accelerometers at sensor locations averaged or omitted depending on availability

Summary


15


An indirect real time metric was used to estimate MPCV loads


Acceleration at LAS shows good correlation with MPCV PEQ loads


Signal processing used to combine accelerations from multiple locations to estimate CG acceleration and lower load projection sensitivity to model errors.





VS tangent loads were measured directly





Metrics were based on peak load


Monitored to ensure PEQ and VS loads stay below enveloped design loads


Did not directly take into account fatigue/fracture concerns, but was consistent with provided time histories for fatigue





While there were some minor data acquisition and software challenges, the effort was largely successful


The ability to monitor vehicle response during rollout in real-time was established


Processes for modifying rollout speed or even halting the CT can be implemented if future needs dictate


Load estimates were largely in the expected range with minor exceedances





Post rollout reconstruction 


Simulations are accurate to within range of design uncertainty values


Observed loads can be better recreated in simulations with minor modeling updates.


VS stiffness increased and VS damping reduced for low amplitude responses


Post-IMT ML model update implemented
