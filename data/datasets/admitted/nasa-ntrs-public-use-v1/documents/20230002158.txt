<p>HybridQ: A Hybrid Quantum Simulator for Large 
Scale Simulations
</p>
<p>Hardware agnostic quantum simulator, designed to simulate large scale quantum circuits
</p>
<p>Can run tensor contraction simulations, direct evolution simulation and Clifford+T
simulations using the same syntax
Features:
</p>
<p>Fully compatible with Python (3.8+)
Low-level optimization achieved by using C++ and Just-In-Time (JIT) compilation with JAX and Numba,
It can run seamlessly on CPU/GPU and TPU, either on single or multiple nodes (MPI) for large scale simulations, using 
</p>
<p>the exact same syntax
User-friendly interface with an advanced language to describe circuits and gates, including tools to manipulate/simplify 
</p>
<p>circuits.
Recent Improvements:
</p>
<p>Commutations rules are used to simplify circuits (useful for QAOA)
Expansion of density matrices as superpositions of Pauli strings accepts arbitrary non-Clifford gates,
Open-source project with continuous-integration, multiple tests and easy installation using either pip or conda
</p>
<p>Open source code available at https://github.com/nasa/HybridQ
S. Mandrà, J. Marshall, E. G. Rieffel, R. Biswas, HybridQ: A Hybrid Simulator for Quantum Circuits, QCS 2021, arXiv:2111.06868</p>

<p>Quantum Distributed Algorithms for Approximate Steiner 
Trees and Directed Minimum Spanning Trees
</p>
<p>• We provide quantum distributed algorithms to tackle challenging graph problems
</p>
<p>• These quantum algorithms provide an asymptotic improvement with respect to the current best known classical 
algorithm in terms of computational rounds in the CONGEST CLIQUE model
</p>
<p>• We provided detailed analysis for the main algorithmic step: finding the all-pairs shortest paths
</p>
<p>• We  obtained complexity results realizing impractical scales where quantum counterparts become better than classical
</p>
<p>• Approximate Stein Tree Problem • Directed Minimum Spanning Tree
</p>
<p>Phillip Kerger, David Bernal Neira, Zoe Gonzales Izquierdo, Eleanor Rieffel</p>

<p>Introduction
</p>
<p>Distributed Graph Algorithms: Network of Multiple Processors that communicate 
</p>
<p>• Model as a graph where the processors are the nodes
</p>
<p>• Each node its own starting information, such as list of neighbors
</p>
<p>9
</p>
<p>• Example: Network of spacecraft, satellites, or control stations that each have 
computing power and can communicate
• Distributed graph algorithms: Answer some question about that graph, by 
</p>
<p>computing across the processors in a distributed fashion</p>
<p></p>
</div>
<div class="page"><p></p>
<p>Introduction: Models
</p>
<p>10
</p>
<p>Graph G = (V,E,W) with n = |V| number of nodes, m = 
|E| number of edges, and W the weights on the edges
</p>
<p>CONGEST Model: Aim is to minimize the number of 
rounds
Computation happens in rounds (compute, 
communicate, compute, communicate, …)
Congested: Communication limited by message size: 
each node can send to each of its neighbors O(log(n)) 
bits each round
</p>
<p>— log(n) is length of a node id
</p>
<p>Unlimited local computation at each node
Nodes can communicate only with their neighbors
</p>
<p>CONGEST-CLIQUE Model: 
1., 2., 3. are the same as for Congest Model
4.   All nodes can communicate with each other 
Key difference: communication graph distinct from 
graph G
</p>
<p>Initial conditions: Each node knows 
• its own ID 
• the ID’s of its neighbors 
</p>
<p>assuming ID’s are 1 to n à log(n) bits to encode 
</p>
<p>Aim: Answer a question about graph in as few rounds as 
possible
</p>
<p>o Ex: Spanning trees, subgraph detection, shortest paths...</p>

<p>Distributed Grover Subroutine
</p>
<p>21
</p>
<p>• Suppose a set X of inputs, and a node 𝑢, which we call the leader, can evaluate a 
</p>
<p>function 𝑔: 𝑋 → {0,1} in 𝑟 rounds. Then there exists a quantum distributed algorithm 
such that 𝑢 outputs an element 𝑥 ∈ 𝑋 with 𝑔 𝑥 = 1 using 𝑂 𝑟 𝑋 rounds.
</p>
<p>• Uses the same ideas as centralized Grover search: search done by leader querying other 
nodes
</p>
<p>• Classical algorithm would use 𝑂 𝑟 𝑋 rounds in absence of additional structure
</p>
<p>• Intuition: A node wants to inquire something related to some subset of other nodes –
instead of inquiring about one node at a time, use superposition</p>
<p></p>
</div>
<div class="page"><p></p>
<p>Aside: Grover’s algorithm
</p>
<p>Grover’s algorithm is the 2nd most famous quantum algorithm after Shor’s factoring 
algorithm
Unstructured search problem: Suppose one has an oracle f: {0, …, N} -&gt; {0,1}. Find a 
marked element (an x such that f(x) = 1) using as few queries to f as possible
</p>
<p>Best possible classically: O(N) queries
Grover’s algorithm can find it using only O(√N) queries to a quantum oracle for f 
</p>
<p>that allows superpositions of inputs and outputs a superposition 
Intuition: make use of quantum interference effects to get non-solutions to cancel 
each other
• It is a special case of “quantum amplitude amplification”
It was proved prior to Grover’s algorithm that quantum algorithms could not do better 
than O(√N) queries 
</p>

<p>Triangle Finding
</p>
<p>Make use of Distributed Grover Search for finding Triangles! 
</p>
<p>Idea: 
• Triangles live in 𝑉×𝑉×𝑉, so partition that space into n subsets 
• Each node searches for triangles in its assigned partition 
• Do this via sets of subsets 𝑉!×𝑉"×𝑉#, where 𝑉! = 𝑉" = 𝑛 ⁄! %, 𝑉# = n ⁄! ",
</p>
<p>and each subset 𝑤 ∈ 𝑉! or 𝑉" contains 𝑛 ⁄# % nodes, and each 𝑤 ∈ 𝑉# contains 𝑛 ⁄! " nodes.
</p>
<p>• So 𝑉!×𝑉"×𝑉# has 𝑛 elements, that are each a partition of nodes in 𝑉×𝑉×𝑉, each node gets 
one partition
</p>
<p>• Making use of fast routing, the bottleneck becomes searching through the elements of 𝑉#;
Grover search can do it in 𝑛 ⁄! % instead of 𝑛 ⁄! "</p>
