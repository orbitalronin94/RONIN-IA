<div class="slide-content"><p>Hypersonic Inflatable Aerodynamics Decelerator (HIAD)</p>
<p>Aeroshell designed to protect and decelerate a spacecraft entering from Low-Earth orbit</p>
<p>Inflatable, allowing Aeroshell to be larger than the rocket’s shroud</p>
<p>6-meter diameter</p>
<p>First Demonstration from Low-Earth orbit</p>
<p>Launched in November from Vandenberg on ULA’s Atlas V</p>
<p>Secondary payload to JPSS-2</p>
<p>Orbited the Earth once, splashing down near Hawaii</p>
<p>2.5 hours between launch and splash down, powered on for about an hour</p>

<p>Threaded Signal Handler behavior ambiguity</p>

<p>Used msg queue for other threads to add and remove signals</p>
<p>Pthread Mutexes were not recursive</p>
<p>Added recursive functionality to OS_mutex</p>
<p>Dynamic Object Loader API inconsistent</p>
<p>Switched to using a module id for all shared object symbol lookups</p>
<p>PSP</p>

<div class="slide-content"><p>Extensive Testing was done to ensure data integrity</p>
<p>Specifically looking for dropped or corrupted packets</p>
<p>Issues were found in four places in the data pipeline</p>
<p>Data not properly routed at the Data Switch</p>
<p>Data not properly received by the Data Recorder</p>
<p>Data not properly written to the SD card by the Data Recorder</p>
<p>Data not properly verified during post-process integrity checks</p>
<p>Data Integrity</p>
<p></p>
<div class="embedded" id="slide20_rId3"></div>
<div class="embedded" id="slide20_rId3"></div>
</div>
<div class="slide-master-content"><p></p>
<p></p>
<p></p>
</div>
<div class="slide-content"><p>Issue:</p>
<p>In testing, significant chunks of data were dropped at the Data Switch once every few minutes</p>
<p>The Data Switch drops packets due to high traffic load</p>
<p>By analysis, average network bandwidth was well under data switch limits</p>
<p>Overall network bandwidth was 20Mbps and the Data Switch was tested up to 60Mbps</p>
<p>Two Solutions</p>
<p>Enable Internet Group Management Protocol (IGMP)</p>
<p>Without IGMP, multicast packets are routed to all connected devices</p>
<p>Each device is expected to drop the packet if it isn’t subscribed to that multicast packet</p>
<p>Resulted in over x6 the bandwidth usage</p>
<p>Camera Pod Controllers sending IR Video</p>
<p>Each of the 6 Camera Controllers sends two IR images at 1Hz</p>
<p>If the images are all sent at the same time, there is a sudden spike in traffic, even though average bandwidth is very small, causing dropped packets</p>
<p>By staggering the image sends, there is never a sudden spike in traffic</p>
<p>Data not properly routed at the Data Switch</p>
</div>
<div class="slide-master-content"><p></p>
<p></p>
<p></p>
</div>
<div class="slide-content"><p>Issue:</p>
<p>The software does not receive the data from the network kernel buffer fast enough, resulting in data being lost in the buffer</p>
<p>Solution:</p>
<p>A thread is created for each multicast address</p>
<p>Each thread does a non-blocking poll to receive data from that address</p>
<p>When no data is available, the thread sleeps to allow another thread to go</p>
<p>Other Attempts:</p>
<p>Using a single thread to receive all of the multicast traffic.  Design was simpler, but the libpcap filter was complex, which slowed overall execution time</p>
<p>Using blocking polls to receive data.  Reduced CPU usage but was overall slower.</p>
<p>Using non-blocking polls with a timeout-based select function. Reduced CPU usage but was overall slower.</p>
<p>Data not properly received by the Data Recorder</p>
</div>
<div class="slide-master-content"><p></p>
<p></p>
<p></p>
</div>
<div class="slide-content"><p>Issue:</p>
<p>Writing to the SD card is a slow process, although theoretical bandwidth is sufficient for the data</p>
<p>Occasional multi-second delays in writes</p>
<p>Solution:</p>
<p>A separate thread for writing data to the SD card</p>
<p>Write data in 10MB chunks, optimizing the throughput</p>
<p>Write each chunk as a separate file</p>
<p>Use a ring buffer to handle the isolated delays</p>
<p>Data not properly written to the SD card</p>
</div>
<div class="slide-master-content"><p></p>
<p></p>

<div class="slide-content"><p>Data Pipeline</p>
<p></p>
<div class="embedded" id="slide24_rId3"></div>
<div class="embedded" id="slide24_rId3"></div>
</div>
<div class="slide-master-content"><p></p>
<p></p>
</div>
<div class="slide-content"><p>Compare data from IDR, EDR, and GSE Data Recorder simulator to verify integrity</p>
<p>Issues</p>
<p>Data Recorders are not started at the same time</p>
<p>Data Recorders are not stopped at the same time</p>
<p>The order of packets in the data file is not guaranteed</p>
<p>Process</p>
<p>Merge the chunk files into one large data file for each Data Recorder</p>
<p>Filter out non data from the network capture</p>
<p>Separate each packet by their source</p>
<p>Write the checksum for each packet into a checksum summary file corresponding to that source</p>
<p>Compare the checksum summary files between two Data Recorders</p>
<p>Search for differences in summary files, ignoring the cases where one has extra packets at the beginning or extra packets at the end</p>
<p>Data not properly verified during post-process integrity checks</p>
</div>
