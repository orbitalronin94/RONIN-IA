<p>Background
</p>
<p> Program to Optimize Simulated Trajectories II (POST2) is a widely used, 
workhorse trajectory simulation tool that has been used to solve a variety 
of atmospheric ascent and entry problems
</p>
<p> Development of POST2 began in the 1970s, and has undergone continuous 
development and updates at NASA Langley Research Center (LaRC) since 
the conversion from all Fortran to C with C++ in the late 2000s
</p>
<p> Significant efforts have led to upgrading POST2 to incorporate modern 
programming paradigms, such as thread safe computations and increased 
modularity and flexibility
</p>
<p>2024 AIAA SciTech Forum 2</p>

<p>Motivation
</p>
<p> Meeting current and future NASA mission requirements may require 
multiple specialized computational tools to interact to properly assess a 
system
• Leverage the strength of each tool to maximize overall performance
• Ex: Couple an interplanetary trajectory design tool with POST2 to allow for optimal 
</p>
<p>end-to-end trajectory solutions
</p>
<p> Problem: how can information be passed between applications in an 
accurate and efficient manner? 
</p>
<p> Solution: an Application Programming Interface (API) allows tools to 
communicate information through pre-defined methods
</p>

<p>API Design Considerations
</p>
<p> Limited file I/O
• For accuracy purposes, no rounding or truncation
• For efficiency purposes, by passing data in memory
</p>
<p> No code duplication
• Ensure execution matches that of stand alone POST2, by utilizing existing code
</p>
<p> Enabling parallelism
• Where possible, make data independent, allowing parallel computations when utilizing 
</p>
<p>the API
</p>
<p>2024 AIAA SciTech Forum 7</p>
<p></p>
</div>

<p>User Controlled Hierarchy
</p>
<p> A workspace contains all the information on simulation setup that is 
defined in a POST2 input file
• Number of available workspaces limited only by available memory on machine
</p>
<p> Workspaces contain one or more trajectories that will each follow the 
simulation setup for that workspace
• Trajectory contains data for one or more vehicles to be simulated
• Number of available trajectories within a workspace limited only by available memory 
</p>
<p>on machine

<p>User Controlled Simulation Settings
</p>
<p> Setting a workspace input is akin to editing an input file and reprocessing it
• No file I/O needed, can modify the POST2 memory directly
• All trajectories within workspace are affected by workspace inputs
• Ex: set ending event for all trajectories to be vertical descent instead of touchdown
</p>
<p> Setting a trajectory value affects only that specific trajectory
• Ex: set integration time step for each trajectory to analyze affect time step size has on

<p>resultant landing location

<p>Example Use Cases of the API
</p>
<p> Since the POST2 API is written in C, many languages and frameworks have 
existing methods that can interface with the POST2 API
• Allows for user to operate in the environment they are most productive in
</p>
<p> Additionally, all inputs and outputs from API methods are primitive C data 
types, to allow for easier interoperability
</p>
<p> Two common platforms used in engineering will be highlighted: Python and 
MATLAB
</p>
<p>2024 AIAA SciTech Forum 14</p>
<p></p>
</div>
<div class="page"><p></p>
<p>Example Use Cases of the API: Python
</p>
<p> C Foreign Function Interface (CFFI) package was used to create callable 
POST2 API module in Python
• Provides a means to operate entirely in a Python process
</p>
<p> Leverage visualization and scientific computing libraries (such as 
matplotlib, numpy, etc.)
</p>
<p> Can also leverage multi-threading capabilities within Python
</p>
<p>2024 AIAA SciTech Forum 15</p>
<p></p>
</div>

<p>Summary
</p>
<p> An application programming interface was developed for a widely used 
flight mechanics tool, POST2
</p>
<p> Allows for interoperability with external applications, with Python and 
MATLAB demonstrated, to maximize performance of tools by leveraging 
the strength of each
• Any language, framework, or application that can interface with C is able to be 
</p>
<p>coupled with the POST2 API
</p>
<p> API will be part of next POST2 release, 
https://www.nasa.gov/post2/requesting
