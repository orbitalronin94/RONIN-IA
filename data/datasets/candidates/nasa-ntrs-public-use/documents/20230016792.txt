<p>Abstract
To perform Micrometeoroid and Orbital Debris (MMOD)
</p>
<p>analyses, NASA describes the orbital debris particle environment using
the ORDEM 3 tool and the micrometeoroid environment using the MEM
3 tool. Both output files that detail the flux of particles as a function of
several parameters. European MMOD analyses use different tools to
perform similar functions, including the Meteoroid And Space debris
Terrestrial Environment Reference (MASTER) environment model,
which outputs flux data in the Standard Environment Interface (STENVI)
format.
</p>
<p>The NASA Johnson Space Center Hypervelocity Impact
Technology Group was asked to create a converter to translate flux data
from the output file formats used by ORDEM 3.x and MEM 3 into the
STENVI file format. Validation was performed to ensure that the
converter was reproducing the input data correctly.
</p>
<p>The Bumper 3 MMOD risk assessment tool has a capability for
reading ORDEM 3.x, MEM 3, and STENVI environment file formats and
was used to compare MMOD risk results generated using the converter’s
output STENVI files to the risk results generated using the input ORDEM
3.x and MEM 3 igloo files. Specific point comparisons validated that the
converter translated the environment data correctly, producing the
intended output. However, realistic risk assessments showed that the bin
methodology employed by Bumper for determining particle flux as a
function of particle size when reading files in STENVI format produces
much higher MMOD risk than the point-interpolation methodology used
in Bumper risk assessments using ORDEM and MEM.
</p>
<p>Modifications to how Bumper 3 reads STENVI files during
analyses are considered to improve Bumper’s ability to perform useful
analyses with environment files in this format.
</p>

<p>Validation
The preferred test for validating that the converter has
</p>
<p>successfully reproduced the input data in the output STENVI file is to run
Bumper analyses to compare the risk result using the new STENVI file to
the risk result using the original ORDEM or MEM input file.
</p>
<p>For all analyses herein, a simple cube with edge lengths of one
meter was run for one year in the environments cited. The cube was
rotated by a small arbitrary amount from the default orientation of each
face pointing at a cardinal direction. This was done to break up potential
symmetry between threat directions as they approach various faces, thus
making the exposure of each face unique and ensuring that tests of the
environment’s directionality were unambiguous.
</p>
<p>To test the conversion of ORDEM (upper table), the ISS orbit was
assessed with Bumper, and to test the conversion of MEM (lower table),
the NRHO trajectory was assessed. In both cases, the environment was
run directly (upper within each table) and run with a STENVI file the
converter produced from the same igloo (middle within each table), with
the differences given (bottom within each table).
</p>
<p>The left-side tables provide the number of impacts by one-
millimeter (ORDEM) or one-microgram (MEM) particles to each face of
the cube, along with the total, for each population and the total. The right-
side tables provide the number of penetrations to a sample Whipple shield
made of a 0.1 cm Al6061-T6 bumper stood off by 10 cm from a 0.3 cm
Al6061-T6 rear wall.
</p>
<p>When assessing impacts of carefully-chosen particle sizes (left
tables), the STENVI results match those using the parent environment
model, indicating that the conversion process successfully translated the
particle flux definitions. The lack of such agreement in the Whipple
shield assessment indicates a practical issue in risk calculation using the
STENVI-formatted files
</p>
<p>Application Challenge
The reason for the difference is in how flux relates to diameter. In
</p>
<p>ORDEM, the flux is provided for a set of fiducial points (specific
diameters) and non-linear interpolation is used to determine the flux for
the critical diameter calculated by Bumper’s Response module. This is
represented by the blue line in the figure below, which graphs particle flux
in log space as a function of diameter. In the present application of a
STENVI file to Bumper, any diameter within a diameter bin is assessed as
having the same flux, which is set by the smallest diameter in the bin.
This is indicated by the red stair-step line in the figure. Therefore, using
STENVI in this way, the flux of 2 mm particles is the same as the flux of
1 mm particles (next lower fiducial point), but for ORDEM, Bumper
interpolates a much lower flux for 2 mm particles based on the
surrounding fiducial points. The one-millimeter impact result matched
exactly because that fixed critical diameter is a fiducial point that sets the
flux for the rest of the STENVI bin—in terms of the graph, the diameter
used was one of the points where the red and blue lines meet.
</p>
<p>A similar phenomenon occurs using MEM regarding its
interpolation mechanism and binning.
</p>
<p>Conversion
The ORDEM and MEM file formats above define particle flux as
</p>
<p>a function of particle size, direction, velocity, and other parameters in a
large table. The converter reads this data and reformats it into the list-
based format below used by STENVI. Necessary assumptions made
during the conversion are listed in the converter tool.
</p>
<p>Conclusion
A converter was created that converts ORDEM 3 and MEM 3
</p>
<p>igloo files into the STENVI format. Converter operation has been
validated via carefully selected Bumper runs matching the risk resulting
from these new STENVI files to the risk resulting from the input igloo
files. In realistic testing, however, the STENVI files result in
substantially higher MMOD risk according to Bumper because flux
values are assigned to all particle sizes in diameter bins, while Bumper
considers ORDEM and MEM flux with much more precision regarding
the intended particle diameter. Potential solutions to this challenge
include 1) implementing the ORDEM &amp; MEM interpolation schemes into
Bumper’s STENVI calculations, or 2) using much smaller particle size
bins to enhance size-flux resolution.
</p>
